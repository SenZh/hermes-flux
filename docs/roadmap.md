# Hermes Aura — 项目全局路线图与研发看板 (Project Roadmap & Status Board)

> **定位说明**：本文档为 Hermes Aura 全平台极客美学工作台（Desktop / Web / iOS / Android）的最高看板与全局路线追踪总表。
> 所有人类工程师与 AI Agent 在领任务、做设计、修缺陷或交付验收时，均以此文档作为**任务对齐基准**与**状态落盘总账**。

## 状态图例规范

- 🟢 **已完成 (Completed)**：已在生产代码落地，且包含 100% 确定性单测/CDP 探针守护
- 🟡 **进行中 (In Progress)**：已有明确技术方案与基础骨架，正在迭代落地中
- ⚪ **规划中 (Planned)**：已完成架构设计与契约论证，等待排期接入
- 🔴 **高危缺陷 (Critical Bug)**：严重影响可用性或破坏核心不变量，阻断交付
- 🟠 **一致性缺陷 (Major Bug)**：契约偏差、状态漂移或交互脱节，暂未引发白屏崩溃
- ⚠️ **技术债 (Technical Debt)**：可维护性、测试假阳性或架构反模式待重构

## 一、系统架构全景与已实现功能 (Implemented Features)

### 1.1 核心通信与协议层 (`packages/core`)
- 🟢 **JSON-RPC 2.0 通信管道与网关客户端**：支持全双工 WebSocket 长连接与请求/响应匹配调度
- 🟢 **5 态连接状态机 (WebSocket FSM)**：包含全抖动指数退避重连算法（`Full Jitter Backoff`）与连接自愈机制
- 🟢 **120FPS 流式 Token 合流引擎 (`TokenCoalescer`)**：微任务级增量合流，防止高频下行事件打爆 DOM 渲染
- 🟢 **契约化事件分发与校验 (`reduceGatewayEvent`)**：覆盖 77 个下行网关事件白名单，拦截畸变 payload 并记录告警
- 🟢 **会话状态与双 ID 映射管理 (`sessionRegistry`)**：隔离 `live_id` 与 `stored_session_id`，适配网关契约边界
- 🟢 **多智能体与群聊核心 Store (`GroupRoomStore` / `ProfileService`)**：承载 Agent Profile 解析与群聊生命周期状态

### 1.2 UI 与表现层 (`packages/ui`)
- 🟢 **极客暗黑设计系统与 Token 引擎**：纯黑深邃底色（`#080808`）、琥珀暖金光晕与翡翠状态指示点
- 🟢 **黄金限宽悬浮输入舱 (`InputDock`)**：严格锁定 740px 居中限宽，支持模型切换与思考深度调整
- 🟢 **会话流式交互与贴底跟随算法**：距底 $\le 48\text{px}$ 自动吸底跟随，历史阅读无跳跃锚定
- 🟢 **长会话 50 条窗口化挂载与触顶步进回补**：首屏仅挂载 50 条，向上触顶以双帧 rAF 平滑拼接 30 条历史
- 🟢 **Markdown / GFM / 思维链 / 工具胶囊基础渲染**：支持代码高亮与折叠推理链
- 🟢 **双列自适应检查舱 (`InspectionPod`) 骨架**：348px 详情工作舱 + 62px 贴窗场景轨（Tab 架构就绪）

### 1.3 跨平台壳工程与交付
- 🟢 **Electron 桌面端 (`packages/desktop`)**：无边框窗口（Frameless）、Cookie 跨域宿主代理与原生系统标题栏
- 🟢 **Capacitor 移动端同构双桥 (`packages/mobile`)**：100% 对齐 16 个平台方法，支持全屏安全区避让与软键盘平滑避让

### 1.4 自动化门禁与研发守护体系
- 🟢 **6 大硬门禁流水线 (`npm run verify`)**：架构规范、TypeScript 零逃逸、反 AI 假测试与设计 Token 强一致
- 🟢 **真实网关 RPC 子进程集成联调 (`npm run test:live-gateway`)**：覆盖 22 个真实 RPC 接口与状态码证伪
- 🟢 **无头浏览器 CDP 物理交互度量 (`npm run test:cdp`)**：真实驱动 Blink 引擎，断言触控热区与视口边界

## 二、当前规划中功能 (Planned Features)

### 2.1 终极三舱架构与多 Agent 深度协同 (v4.5 Spec)
- ⚪ **左侧双轨主线 (Dual Left Rail)**：48px 极窄微轨（工作区/Bot/群聊快速切换）+ 212px 可折叠主抽屉

- ⚪ **右侧工具舱真实数据驱动**：
  - ⚪ **成果物画廊 (Artifacts)**：真实消费 `tool.complete` / 文件写入事件，提供可交互预览与导出
  - ⚪ **无头浏览器视窗 (Browser Live View)**：订阅 `browser.frame` / `browser.progress` 实时投影网页操作
  - ⚪ **代码时光机 (Git & Workspace Diff)**：集成 `rollback.diff` / `rollback.restore` 实现快照点级撤销与对比
  - ⚪ **长程记忆与知识洞察 (Cognitive Memory)**：实时提取会话上下文，展示 Profile 长期记忆快照

### 2.2 中间核心交互区与输入舱全面升级 (Interactive Conversation Stage & Composer Spec)
- ⚪ **对话展示流微距交互**：
  - ⚪ **常驻微距操作栏**：用户消息提供复制、回滚（带输入框自动回填与历史截断）、Fork（派生独立 Session）；AI 消息提供复制、基于当前节点 Fork
  - ⚪ **阶梯式 Token 与性能仪表**：外层常驻总 Token 胶囊，点击/Hover 展开展示实时 TPS、调用模型全名、输入/输出 Token、缓存命中数及命中率
  - ⚪ **群聊与单聊身份头栏**：群聊强显出话 Agent 头像、专属昵称与颜色指纹
  - ⚪ **工具调用智能折叠**：读类工具自动收敛为 28px 单行胶囊，写类工具展开 Diff 并支持投射至检查舱深钻
- ⚪ **悬浮输入舱与队列深度赋能 (Composer Dock & Queue Manager)**：
  - ⚪ **待发送消息队列管理**：多条消息排队托盘，支持单条取消、自由调序、重新编辑回填，支持一键 `session.interrupt` 紧急刹车并插队
  - ⚪ **Provider 折叠手风琴模型选择器**：按厂商折叠展开，支持即时搜索与 Context 上限/多模态标签

  - ⚪ **斜杠命令与 Skill 补全**：`/` 唤起补全悬浮面板，系统命令与已注册 Skill 混合检索，上屏等待补全参数
  - ⚪ **`@` 智能引用差异化调度**：普通会话支持 `@file`（工作区/知识库路径）与 `@agent`（单次委派）；Bot 专职工位禁用 `@agent`；群聊支持 `@all` 与特定成员唤醒

## 四、现有已知 Bug 与待修复缺陷 (Known Issues & Bug Tracker)

### 4.1 🔴 高危缺陷 (Blockers / Critical)

#### BUG-001：连接闪断后客户端界面状态未与底层 FSM 真实联动
- **现象**：网关服务闪断或网络重置后，底层 WS 客户端虽已重连，但桌面界面仍处于未连接态（输入舱不展示）。
- **根因**：`packages/desktop/src/renderer/index.ts` 监听了初始的旧 WebSocket 实例，重连新建实例后事件脱钩。
- **修复方案**：渲染层统一切换为订阅 `HermesGatewayClient.fsm.onStateChange`，并在状态进入 `CONNECTED` 后主动刷新会话列表与兑换 `live_id`。

#### BUG-002：删除正在运行中的会话导致网关报错且用户无感知引导
- **现象**：用户在侧边栏点击删除一个正在流式运行的会话，网关返回 `4023 cannot delete an active session`，仅显示浮动报错。
- **根因**：未在前置交互层做状态拦截，亦未自动执行前置中断。
- **修复方案**：对 `running` 状态会话删除按钮置灰，或在点击删除时先调用 `session.interrupt`，再执行 `session.delete`。

### 4.2 🟠 一致性与正确性缺陷 (Major)

#### BUG-003：群聊消息非流式且未绑定发言 Agent 头像与名称
- **现象**：群聊中 Bot 发言无法实时流式滚动，必须离开重进；发言气泡无法准确区分来自哪位 Agent。
- **根因**：群聊长连接事件未对齐消息合流管道；渲染层未解析 `speaker_id` 关联 Profile 资产。
- **修复方案**：对接 `groups.log` 增量推送与 `message.delta`，按 `sender` 注入 Agent 头像与昵称标签。

#### BUG-004：InspectionPod（检查舱）四个子面板处于纯空态
- **现象**：成果物、浏览器、Git 变更与记忆四个 Tab 无法获取数据。
- **根因**：渲染层监听的事件名并非网关原生契约事件，属于历史占位逻辑。
- **修复方案**：通过解析 `tool.complete`（文件生成）与 `sessions.changed` 驱动成果物及变更比对；在真实数据源未就绪前，按 Gate 4 原则收敛展示。

#### BUG-005：历史会话重新载入时丢失思维链与工具卡片
- **现象**：打开旧会话时，`session.resume` 仅还原纯文本消息，当时生成的思考链（Thinking）与工具调用胶囊未呈现。
- **根因**：网关历史查询接口返回的数据结构不包含瞬时事件上下文。
- **修复方案**：在本地存储对会话事件流做增量落盘，或探测网关事件日志接口补齐重放能力。

#### BUG-006：跨 Provider 同名模型切换报 `5001` 与未声明 `provider` 导致 CONTRACT_VIOLATION
- **现象**：切换模型时抛出 `[CONTRACT_VIOLATION] RPC "config.set" 传入了网关契约未声明的字段 [provider]`，或在多 Provider 同名时报 `5001 Model ambiguity`。
- **根因**：前端代码在向 `config.set` 传参时擅自包装了 `provider` 字段，直接触发了客户端运行期契约守卫（`config.set` 官方只接受 `[profile, key, value, session_id, scope, confirm_expensive_model]`）。
- **修复方案**：已在客户端严格剔除顶层 `provider` 冗余参数，保持纯净契约调用；并在中长程架构上记录模型全局激活 Provider 与中继设计方案。

#### BUG-007：工具执行打包卡片状态不更新、内容显示 [object Object] 与正在执行命令未呈现
- **现象**：① 工具卡片展开后内容出现 `[object Object]`；② 多个工具全部完成时，总揽状态仍滞留在“正在执行 (5/6) · 已完成 1”；③ 顶栏“正在执行”处没有实时呈现当前正在执行的具体命令字符串。
- **根因**：工具 output 解析未安全做字符串格式化，且 tool 终态事件未实时驱动卡片状态重新计算。
- **修复方案**：强化工具 output 解析（对象类型通过 `JSON.stringify` 漂亮排版），在卡片顶部实时提取 `running` 工具的命令名/参数并滚动展示，对齐 `tool.complete` 事件刷新状态。

#### BUG-008：会话/Bot/群聊三态指示器未生效
- **现象**：运行态无呼吸脉冲点，已完成未读态无小圆点。
- **根因**：渲染层未从真实事件流（`message.start` / `message.delta` / `message.complete`）中把运行中会话与未读标记正确打上，或在初次加载时被误重置。
- **修复方案**：将活跃流式状态与会话 ID 强绑定，并在状态转移时即时更新左轨指示器 DOM。

#### BUG-009：群聊右键复制 ID 时在底部输入框弹出 notice 提示破坏排版
- **现象**：右键复制 ID 会在底部输入舱里冒出通知条。
- **根因**：复制动作复用了 `state.dockNotice`。
- **修复方案**：剥离 `dockNotice`，改为轻量、独立的全局微型 Toast 气泡，不再污染输入舱。

#### BUG-010：群聊右键“重命名”不生效
- **现象**：点击重命名后群聊名称没有变。
- **根因**：网关契约 `groups.rename` 成功返回 `{ room }`，但前端未捕获新的房间信息并同步更新 `state.groupRooms`。
- **修复方案**：重命名成功后直接读取响应中的 room 并刷新左侧轨道。

#### BUG-011：会话关联 Workspace 徽章未在顶栏出现、项目抽屉无列表
- **现象**：打开有项目的会话顶栏不显示工作区徽章；切换到项目面板时不显示项目列表。
- **根因**：`fetchProjects()` 未在会话加载完成后建立有效映射，或会话缺少正确的 `projectId` / `cwd`。
- **修复方案**：在初始化与会话切换时主动拉取并同步 project 列表，顶栏和项目抽屉统一消费。

#### BUG-012：删除会话后所有会话输入框无法键入 (Input Dock Lockout on Delete)
- **现象**：用户在左侧右键删除某个会话后，无论是当前残留会话还是切换到其他会话，底部输入框都无法输入文字（打字无反应、键盘无响应）。
- **根因**：会话删除时残留草稿键污染、流式看门狗未自愈重置、或者 DOM 树局部重建后输入框未重新绑定事件与恢复焦点。
- **修复方案**：已在底层清理关联缓存与流式标记，并在渲染后跨帧 `rAF` 恢复焦点；待真实联调验证通过。

## 六、Agent 研发协同指导原则 (Agent Autonomous Guidelines)

1. **领任务必查**：动手前必须通读本文件第四节的已知 Bug 与第三节的 Backlog，严禁重复踩已知坑。
2. **修 Bug 必守**：修复缺陷后，必须在 `docs/architecture/pitfall-registry.md` 登记对应坑位、根因与守卫探针。
3. **改完必验证**：严格执行三位一体交付命令（`npm run verify`、`npm run test:live-gateway`、`npm run test:cdp`）。
4. **结项必回写**：任何功能合入或 Bug 修复，必须在本文档对应条目更新状态标记（由 🔴/⚪ 变更至 🟢），保持看板绝对保真。
