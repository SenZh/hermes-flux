# 提供商配置：裁决版需求 (2026-11-11)

状态：**已裁决，作为实现与验收的唯一真值。**
凡与 [`design.md`](./design.md) 冲突处，以本文为准；差异清单见 §11。

前置事实来自 `design.md` 的源码与网关取证，本文不重复取证，只固化裁决后的语义、作用域与闭环。

## 0. 裁决摘要

| # | 问题 | 裁决 |
|---|---|---|
| 1 | Provider 与 Agent 的关系 | **一行 provider = 一个 id + 一组 Agent 成员**；没有脱离 Agent 的全局实体 |
| 2 | 自定义端点新增 / 编辑的作用域 | 表单直接多选「生效于」哪些 Agent；保存时对每个成员各写一份 |
| 3 | 删除的作用域 | 删除 = 从全部成员 Agent 上移除；有 active 成员则禁止 |
| 4 | 跨成员副本不一致 | **强制写一致**：定义字段一致；密钥独立 |
| 5 | 保存是否设主模型 | **加显式开关**，默认关闭 |
| 6 | 测试连接是否改输入 | **自动回填**，且回填可见、可撤销 |
| 7 | 订阅登录态读取 | **按 profile 全量拉取** |
| 8 | 删除前置读取完整性 | **三层都完整才允许删除**：roster + `model.options` + 成员清单 |
| 9 | 新建端点是否允许无密钥 | **不允许** |
| 10 | 端点 id 是否可编辑 | **不允许**；新建时可填，保存后只读 |
| 11 | 部分失败后的重试 | **全量重写**，操作必须幂等 |
| 12 | 自定义端点单点操作的默认 Agent | 默认当前连接 profile，按钮/标题写明目标，可改，不记忆 |
| 13 | 订阅的生效范围 | **默认全部 Agent 生效**：登录一次共享（`share_auth` 回落），行内格子只读，退出登录是唯一撤销入口 |

## 1. 边界

### 1.1 纳入

| 能力 | 说明 |
|---|---|
| 自定义端点实体 | 创建、编辑、删除；每个成员 Agent 一份副本 |
| 成员集合 | 某 provider id 在哪些 Agent 上存在；多对多 |
| 订阅登录态 | 登录、轮询、取消、退出；按 profile 独立 |
| 主模型槽位 | 每个 Agent 恰好一个 `(provider, model)` |
| 删除 | 从全部成员上移除来源实体 |
| 诊断 | 测试连接、读取失败、部分失败、定义漂移 |
| 跨 profile 副作用 | 首次写入提示与回归验证 |

### 1.2 排除

| 不做 | 理由 |
|---|---|
| 修改网关 `config.yaml` 的物理格式 | 只走已有 REST/RPC |
| 订阅购买、套餐管理 | 网关无契约 |
| 复制订阅登录态到别的 Agent | `share_auth` 下新 profile 只读回落，不可写 |
| 跨 provider 的一次性批量操作 | 每次写都可能触发托管切换，副作用叠加不可控 |
| provider 的“全局实体” | 物理上不存在，只有各 profile 副本 |
| 同一 id 在不同成员上使用不同 `base_url` | 裁决 4：强制写一致；需要不同地址就用不同 id |
| “N/M 生效”计数 | 分母不可解释；Agent 槽位本身就是全集 |
| 密钥回显 | GET 不回明文 |
| 不带密钥的自定义端点 | 裁决 9；无鉴权端点不在本期范围 |

### 1.3 判据

只有同时满足以下三条的能力才进本期：

1. 每个 profile 各有一份物理副本；
2. 有真实的 REST/RPC 写入口；
3. 写完能回读验证。

## 2. 四层模型

| 层 | 语义 | 物理位置 | 基数 | 写入口 |
|---|---|---|---|---|
| **Provider 实体** | 一个模型来源的统一定义 | 各成员 profile 的 `config.yaml` + `.env` | 逻辑一个，物理 N 份 | 保存 / 删除 |
| **成员集合** | 这个 provider id 存在于哪些 Agent | 各 profile 的端点清单 | 多对多 | 「生效于」多选 / 行内格子 |
| **ActiveModel** | 某 Agent 此刻用它的哪个模型 | 网关 `model/set` 的 `main` 槽 | 每 Agent 恰好一个 | 模型列表点选 |
| **LoginState** | 某 profile 是否持有某订阅的 OAuth 令牌 | 各 profile 的 `auth.json` | 每 profile 独立 | 登录 / 退出 |

### 2.1 一行 provider 的定义

```
ProviderRow = {
  id: 稳定主键,                 // 保存后不可改
  definition: 统一定义,          // 所有成员必须一致
  members: Agent[],             // 仅自定义端点：成员集合 = 配置集合
  agents: AgentSlot[],          // 每个 Agent 的槽位状态
}
```

**成员集合只适用于自定义端点。** 订阅是账号级来源，没有按 Agent 的成员集合：
登录一次默认对所有 Agent 生效（`share_auth` 回落），行内格子只读，退出登录是唯一撤销入口。

三条硬约束（自定义端点）：

1. **没有成员就没有这一行。** 成员集合为空 = 数据不一致，记 warn，不渲染成“没有 Agent 在用”。
2. **成员集合是删除与编辑的作用域，`model.options` 是在用集合。** 两者不可互换。
3. **成员存在 ≠ 可用。** 成员可能有 `key-missing`（缺密钥）、`drift`（定义漂移）、或未进入 `model.options`（未生效）。

### 2.2 成员真值来源

| 来源类型 | 成员真值 | 在用真值 | 登录态真值 |
|---|---|---|---|
| 自定义端点 | 端点清单 `ProviderCatalogEndpoint.profiles` | `model.options.is_current` | — |
| 订阅 | **全部 Agent**（登录一次共享） | `model.options.is_current` | 共享 auth（`share_auth` 回落） |

`model.options` **不能**单独作为自定义端点的成员判定依据：端点可以存在于某 profile 的配置里、却没进 `model.options`（未生效、未带模型）。当前实现用 `model.options` 当唯一基座，会把这类成员显示成“未配置”。

订阅相反：`model.options` 只用来判断 `active`；没有命中不代表该 Agent 不能用，只代表它当前没有把这个订阅设为主模型。

## 4. 操作目标矩阵

### 4.1 需要选 Agent 的操作

| 操作 | 目标 | 形态 | 默认 | 合法范围 |
|---|---|---|---|---|
| 新建自定义端点 | 成员集合 | 「生效于」多选，至少一个 | 当前连接 profile | 全部 Agent |
| 编辑自定义端点 | 成员集合 + 统一定义 | 「生效于」多选，可增删成员 | 当前成员 | 全部 Agent；取消 active 成员被阻止 |
| 设为当前模型 | 单个 Agent | 模型列表顶部单选 | 当前连接 profile | 自定义端点只列成员；订阅默认全部 Agent |
| 绑定勾选/取消（仅自定义端点） | 单个 Agent | 格子就地 | — | 见 §7 状态机 |
| 补密钥（仅自定义端点） | 单个 Agent | 格子就地 | — | 该 Agent 是成员且缺密钥；优先从其它成员复制，复制不到才要求手填 |

订阅登录 / 退出不选 Agent：登录一次作用于共享 auth，默认全部 Agent 生效；行内格子只读。

### 4.2 全体操作（不选单个 Agent）

| 操作 | 目标 | 界面必须显示 |
|---|---|---|
| 订阅登录 | 共享 auth | 登录成功后所有 Agent 可用 |
| 退出订阅登录 | 共享 auth | 退出后所有 Agent 失去该订阅 |
| 删除来源实体 | 全部成员（自定义） | 受影响 Agent 完整名单 |
| 定义漂移统一 | 全部成员（自定义） | 漂移 Agent 名单与差异字段 |
| 首次跨 profile 写入提示 | 本次写入涉及的全部 profile | 提示只出现一次，写后回归验证 |

### 4.3 只读操作（不需要选 Agent）

查看模型、搜索、展开/收起、重试读取。

### 4.4 默认值与记忆规则

- 多选默认只勾当前连接 profile；单点默认当前连接 profile。
- 界面必须把目标 Agent 写出来；多选必须显示已选成员数。
- 不记忆上一次选择：每次打开表单/弹窗从默认值开始。
- 选择器只列对该操作合法的 Agent；非法项不出现，而不是出现后报错。
- 破坏性操作（退出登录、删除、取消 active 成员、统一漂移）的确认框必须再写一次目标 Agent 名单。

## 6. 统一定义与成员写入（裁决 4）

### 6.1 一致字段

以下字段在所有成员上必须相同：

`name`、`base_url`、`model`、`models`、`model_details`、`context_length`、`api_mode`、`discover_models`。

### 6.2 密钥规则

`api_key` **不强制一致**，原因：GET 不回明文，客户端无法读回其他成员的原密钥。

| 场景 | 密钥行为 |
|---|---|
| 新建 | 一个密钥分发到所有选中成员；这是唯一能分发明文的时刻 |
| 编辑，密钥留空 | 每个成员保留各自原密钥（`keep`） |
| 编辑，填写新密钥 | 同步写入所有保留成员 + 新增成员（用户明确覆盖） |
| 编辑，有新增成员 | 密钥必填；否则新增成员无法创建 |
| 补密钥 | 只写该成员，不改定义 |
| 移除成员 | 不影响其他成员的密钥 |
| 取消后重新勾选 | **优先从其它成员复制**：读源成员的端点行，取 `api_key_preview` 的 `${ENV_VAR}`，调 `POST /api/env/reveal` 取明文后写入目标成员；源成员没有可读 `key_env` 时才要求用户手填 |
| 所有成员都没有可读密钥 | 允许手填；不回退成"无密钥写入"，也不把脱敏预览当密钥 |

### 6.3 成员集合的写入顺序

新建：

```
校验草稿（名称/地址/模型/密钥/至少一个成员）
  → 逐个成员 POST（定义 + 密钥）
  → 每个成员的结果单独记录
```

编辑：

```
1. 先写保留成员的新定义（密钥留空则 keep，填写则覆盖）
2. 再写新增成员（定义 + 本次密钥）
3. 定义全部写成功后，再删除被取消的成员
4. 若任一保留/新增成员写失败，停止后续步骤，不执行成员移除
```

先写后删，避免中途失败把 provider 从所有成员上删掉。

### 6.4 漂移检测与初始值

- 读取时逐个成员比较定义字段（`base_url` + `model` + `models`）。
- 不一致的成员槽位带 `drift` 标记，并给出差异字段。
- 行级显示「N 个成员的定义不一致」；提供「统一为表单定义」入口（B24）。
- 打开编辑时，若存在漂移：
  - 默认以当前连接 profile 的副本为初始值（若它不是成员，则取第一个可读成员）；
  - 顶部提示「这些成员的定义不一致，保存将统一为以下值」；
  - 允许用户切换初始值来源。
- `diffEndpointAcrossProfiles` 从死代码转为漂移检测的真值来源。

### 6.5 失败与重试

- 全量重写：重试重新执行整次保存，包含已成功的成员。
- POST 同 id 是 upsert；重复写相同定义幂等。
- 重试结果覆盖旧结果，不追加历史。
- 部分失败时不得 toast「已保存」。

## 7. Agent 槽位状态机

### 7.1 主状态（互斥，自定义端点）

| 状态 | 判定 | 格子 | checkbox | 可执行 |
|---|---|---|---|---|
| `active` | 是成员，且 `model.options.is_current` 指向该来源 | 高亮 + “当前模型” | 已勾选，禁用 | 先换模型 |
| `ready` | 是成员，已可用但非当前模型 | 常规 | 已勾选，可取消 | 取消成员 |
| `absent` | 不是成员 | 弱化 | 未勾选 | 勾选 |
| `error` | 本次读取失败 | 弱化 + 原因 | 未勾选，禁用 | 重试 |

订阅的 `ready` 与 `active` 都只读：登录一次默认全部 Agent 生效，没有按 Agent 可写的绑定。

### 7.2 附加标记（可叠加，自定义端点）

| 标记 | 判定 | 含义 | 操作 |
|---|---|---|---|
| `key-missing` | 是成员但 `has_api_key=false` | 成员存在，发不出请求 | 补密钥 |
| `drift` | 定义与统一定义不一致 | 副本漂移 | 统一为表单定义 |

`key-missing` 与 `drift` 可以叠加在 `active`/`ready` 上。
`error` 不得被渲染成 `absent`（Failure Is Not Empty）。

### 7.3 订阅槽位：默认全部生效

| 登录态 | 是否在 `model.options` | 槽位 | checkbox |
|---|---|---|---|
| 已登录 | 是，且 current | `active` | 已勾选，只读 |
| 已登录 | 是，非 current | `ready` | 已勾选，只读 |
| 已登录 | 否 | `ready` | 已勾选，只读 |
| 未登录 | — | 该订阅不进主列表 | — |
| 任一读取失败 | — | `error` | 未勾选，禁用 |

### 7.4 可用性圆点

行级 `availability` 仍为四态：`active` / `ready` / `error` / `not_configured`。
有任一 Agent `error` 时行级为 `error`；圆点文案必须区分“读取失败”与“来源不可用”。

## 8. 业务闭环

### 8.1 新接自定义来源 → 给 N 个 Agent 用

```
添加提供商 → 自定义页
  → 填名称/地址/密钥/模型
  → 测试连接（成功自动回填，可撤销）
  → 「生效于」多选：勾选 N 个 Agent（默认当前连接 profile）
  → 决定「同时设为当前模型」（默认关；若开，选成员中的一个）
  → 保存
  → 逐个成员写入定义 + 密钥
  → 回读每个成员的端点清单与 model.options
  → 视图逐 Agent 显示 ready / key-missing / drift
  → 用户再为某个成员点模型设为 active
```

### 8.2 新登录订阅 → 默认全部 Agent 生效

```
添加提供商 → 订阅页
  → 选订阅 → 登录 → 设备码 / 轮询 approved
  → 登录态写入共享 auth（share_auth 回落）
  → 回读 oauth 目录与每个 Agent 的 model.options
  → 所有 Agent 槽位默认 ready，格子只读
  → 用户再为某个 Agent 点模型设为 active
```

### 8.3 编辑 provider：只改定义（自定义端点）

```
点编辑
  → 只改定义：名称 / 地址 / 密钥 / 模型；端点 ID 只读
  → 不出现 Agent 列表；成员在列表页「生效于」中增删
  → 保存只写统一定义
  → 回读全部成员
```

### 8.4 行内追加/移除成员

```
自定义：
  勾选 absent 格子 → 先按配置集合找其它成员 → 读其 `${ENV_VAR}` 并复制明文
    → 有可读来源：直接写入该 Agent
    → 无可读来源：就地补密钥 → 写该 Agent
  取消 ready 格子 → 从该 Agent 删除副本 → 移出成员
订阅：
  所有格子只读（登录一次默认全部 Agent 生效）
  退出登录作用于共享 auth；退出后所有 Agent 失去该订阅
active：
  禁用，先换模型
```

### 8.5 切换某 Agent 主模型

```
展开模型 → 选择目标 Agent（默认当前连接 profile；自定义端点只列成员，订阅列全部 Agent）
  → 点一个模型
  → /api/model/set
  → 回读 is_current
  → 该 Agent 变 active，原 provider 变 ready
```

### 8.6 删除来源实体

```
点删除
  → 前置：roster 完整 + model.options 全部成功 + 成员清单全部成功
  → 有 active：禁止，列名单 + 去切换模型
  → 成员集合为空：记数据不一致，不弹“没人在用”
  → 逐成员 DELETE
  → 全部成功：行消失
  → 部分失败：保留未删项，列名单，重试全量
```

### 8.7 定义漂移统一

```
行内显示 drift 与差异 Agent
  → 「统一为表单定义」
  → 逐成员重写定义（密钥 keep）
  → 回读，漂移标记消失
  → 部分失败：列名单，重试全量
```

### 8.8 首次跨 profile 写入

```
检测首次跨 profile
  → 明确提示：网关将切换为多 profile 托管，未带 scope 的凭据读取将 fail closed
  → 用户确认
  → 执行写入
  → 回归验证：重拉 profiles / model.options / 会话列表
  → 失败：停止继续写，给重连入口
```

## 9. 流程闭环

### 9.1 读态

`idle → loading → ready | error`，每个数据源独立：

- 每个 Agent 的 `model.options`；
- 每个 Agent 的 `providers/oauth`；
- 每个 Agent 的 `providers/custom-endpoints`；
- roster。

合并后每行有 `availability`，每个 Agent 槽位有主状态 + 附加标记。

### 9.2 写态

`idle → pending → success | partial | failed`。

`partial` 不是成功；`failed` 保留草稿与原始原因。

### 9.3 删除态

`blocked-in-use | blocked-incomplete | ready | empty`。

- `blocked-in-use`：有 active，禁止。
- `blocked-incomplete`：三层任一读取失败或 roster 不完整，禁止。
- `ready`：成员集合非空且无以上阻塞。
- `empty`：数据不一致，记 warn，不弹“没人在用”。

### 9.4 不变量

| 编号 | 不变量 |
|---|---|
| I1 | 每个 Agent 恰好一个 active；active 的 provider 必须存在 |
| I2 | 自定义端点的成员集合用于编辑与删除，在用集合用于禁止删除，两者不可互换 |
| I3 | `error` 绝不渲染成 `absent` |
| I4 | 部分失败不得报“已删除/已保存” |
| I5 | 每次写后必须回读，界面状态以回读为准 |
| I6 | 目标 Agent 在用户点下按钮的瞬间锁定，确认期间切换不改变目标 |
| I7 | 首次跨 profile 写入必须提示并回归验证 |
| I8 | 订阅登录一次默认所有 Agent 共享；退出登录作用于共享 auth；不得伪造按 Agent 的订阅绑定 |
| I9 | 自定义端点的定义字段在所有成员上强制一致；密钥独立；一致不等于可用 |
| I10 | 删除自定义端点前 roster、`model.options`、成员清单三层都完整 |
| I11 | 重试全量重写；POST upsert、DELETE 404 视为已达成 |
| I12 | 任何新增成员必须有密钥；没有密钥的成员只能以 `key-missing` 存在。密钥优先从其它成员的 `key_env` 复制，复制不到才允许手填 |
| I13 | 自定义端点的行内格子与表单「生效于」是同一份成员集合，双向同步；订阅格子只读 |

### 9.5 刷新与竞态

- 保存/删除/登录/退出/统一漂移后自动全量重拉。
- 外部变更靠失败态重试或重进设置页覆盖，不设常驻刷新。
- 每个异步装载带自增令牌，后发先至以最后一次为准。
- 登录轮询绑定启动时的 `(profile, provider, sessionId)`，切换作用域不影响进行中的会话。
- 弹窗关闭必须取消进行中的登录会话。

## 10. 验收标准（EARS）

```
WHEN 用户新建自定义端点
THEN 必须至少勾选一个「生效于」的 Agent，且密钥必填；
    保存后每个选中 Agent 的端点清单都出现它。

IF 用户新建端点时未填密钥或未选任何 Agent
THEN 保存按钮不可点，并说明缺什么。

WHEN 用户测试连接成功
THEN 地址被回填为网关解析的 resolved_base_url；若默认模型为空则回填首个模型；
    回填处可见“已按探测结果回填”，并提供恢复原值。

IF 测试连接失败
THEN 草稿的地址、模型、密钥字段不得发生任何变化。

WHEN 用户编辑一个已在多个 Agent 上配置的端点
THEN 编辑弹窗只显示定义字段，不出现 Agent 列表；
    保存后所有成员的定义字段一致；成员增删在列表页「生效于」网格完成。

WHEN 用户打开编辑弹窗
THEN 端点 ID 只读，并说明保存后不可修改。

IF 成员之间存在定义漂移
THEN 编辑打开时提示差异，允许切换初始值来源；保存后统一为表单值。

IF 某个成员缺密钥
THEN 定义同步成功，但该 Agent 槽位标“缺密钥”，并给补密钥入口。

WHEN 用户在编辑表单勾选一个尚未配置该端点的 Agent
THEN 该 Agent 成为新增成员，表单要求输入密钥；保存时写入定义 + 本次密钥。

WHEN 用户在编辑表单取消一个 active 成员
THEN 保存被阻止，并提示先为该 Agent 切换模型。

WHEN 用户点击列表页的 Agent 格子（自定义端点）
THEN 勾选立即写入：未配置时先尝试从其它成员复制密钥，复制成功则直接成为成员；
    只有所有成员都没有可读密钥时，才就地补密钥；取消勾选时从该 Agent 删除副本；
    成功回读，失败回滚该格并给原因。

WHEN 用户取消一个成员后又在同一行把它勾回来
THEN 只要其它成员仍持有该端点且密钥可通过 `key_env` 读取，
    不得再要求用户输入 API Key；写入后回读，成员恢复。

WHEN 一个订阅已登录
THEN 所有 Agent 的格子默认勾选且只读，并说明“订阅登录后对所有 Agent 生效”；
    退出登录是唯一撤销入口。

WHEN 用户退出一个订阅
THEN 作用于共享 auth；退出后所有 Agent 失去该订阅，而不是只影响某一个 Agent。

WHEN 用户在模型列表点一个模型
THEN 必须明确作用于选择器选中的 Agent；默认当前连接 profile；
    按钮/标题包含该 Agent 名称。

IF 网关要求高价模型确认
THEN 弹窗保留，显示网关原文；“仍然设置”带 confirm_expensive_model 重发。

WHEN 用户保存端点且“同时设为当前模型”开关关闭
THEN 主模型不得改变，只写端点定义与成员关系。

WHEN 用户删除一个来源实体
THEN 必须要求 roster、model.options、成员清单三层读取完整，且无 active；
    任一不满足则禁止删除并列出阻塞原因。

IF 删除过程中某个成员失败
THEN 已删除的保持已删除，未删除的保留成员资格，行内列出失败 Agent 与原因，
    不出现“已删除”提示；重试执行全量删除。

WHEN 用户重试一次部分失败的保存或删除
THEN 重新执行整次操作，包含已成功成员；POST 重写幂等，DELETE 404 视为已达成。

WHEN 读取发现同一来源在各成员上的定义不一致
THEN 对应 Agent 槽位标“定义漂移”，行内给出差异字段与“统一为表单定义”入口。

IF 某个 Agent 读取失败
THEN 该格显示失败原因并禁用，绝不可渲染成“未配置”。

WHEN 首次发生跨 profile 写入
THEN 写前给出多 profile 托管切换提示；写后回归验证 profiles / model.options / 会话列表。

WHEN 订阅登录进行中用户切换目标 Agent
THEN 进行中的会话仍绑定启动时的 Agent，不因切换而写到别的 Agent。

WHEN 端点存在于某 Agent 的配置里但没有进入 model.options
THEN 该 Agent 仍显示为成员（ready），不得显示成 absent。
```

## 13. 实施顺序建议

1. **成员集合层**：视图的 Agent 槽位改用成员真值（端点清单 / OAuth）；补 `key-missing`、`drift`、`login-required`；`bindingFor` 补 `detail`。
2. **成员编辑器**：新建/编辑表单的「生效于」多选；行内格子与表单共享同一份成员集合；取消 active 成员阻止。
3. **写路径**：逐个成员写入 → 强制一致 → `make_default` 开关 → 全量重试。
4. **订阅层**：按 profile 全量拉目录 → 行内“去登录/退出登录” → 登录会话锁定目标。
5. **诊断层**：测试回填可见可撤销 → 三态归类 → 漂移统一。
6. **清理**：死代码、死文案、双真值、轮询清理。
7. **验收**：按 §10 落盘测试，补 E2E 闭环。

## 14. 明确不做

| 不做 | 理由 |
|---|---|
| 无鉴权自定义端点 | 裁决 9 |
| 端点 id 重命名 | 裁决 10；id 是物理主键 |
| 同一 id 在不同成员上使用不同 `base_url` | 裁决 4；需要不同地址就用不同 id |
| 跨 provider 批量操作 | 托管切换副作用不可控 |
| 订阅登录态复制 | 物理不可能 |
| “N/M 生效”计数 | 分母不可解释 |
| 常驻刷新按钮 | 写后自动重拉，失败态有重试 |
| 所有成员都没有可读密钥时静默追加 Agent | 无法凭空恢复明文；必须让用户手填一次 |

## 15. 界面交互补充（2026-11-11 实测反馈）

### 15.1 Agent 成员格：头像即操作面

| 决策 | 说明 |
|---|---|
| 去掉正方形卡片框 | 用户实测反馈"头像外面那圈方框多余"；边框会吃掉宽度，头像只能做到 24px |

| 当前模型用 success 环 | 头像外 2px success 环 + 名称加粗；图例行明确写"勾选 = 已配置 · 绿环 = 当前模型" |
| 读取失败 | 头像虚线红边 + 右上角红点，保持锁定与原因透出 |
| 网格横跨整行 | 标题与动作按钮单独占一条；网格不再被动作按钮挤窄，避免同一名单在不同行排出 4 列 / 5 列 |

### 15.2 查看模型：弹框 + 共用模型行

| 决策 | 说明 |
|---|---|
| 不再行内展开 | 行内展开会把提供商表撑成大列表；模型列表进入独立弹框 |
| 复用模型行 | 图标 + `parseModelDisplay` 计算出的完整可读名 + 变体 / 量化 / 上下文标签 |
| 不直出模型 ID | 可见文本只出现可读名；ID 仅用于写回与 React key |
| 当前模型标注 | 按当前作用域 Agent 的 `active` 槽位定位，弹框内显示"使用中" |
| 高价模型确认 | 网关回 `confirm_required` 时弹框不关，显示原文与「仍然设置」，不再叠第二层弹窗 |

### 15.3 端点编辑：默认模型选择器

| 决策 | 说明 |
|---|---|
| 下拉选择 | 点击默认模型字段弹出可用模型列表，列表复用 15.2 的模型行 |
| 保留手动输入 | 首次创建、尚未探测模型时必须能直接填模型 ID；下拉内提供「手动输入模型 ID」入口 |
| 选中态显示可读名 | 选择后字段显示图标 + 计算名，不把裸 ID 当标签 |
