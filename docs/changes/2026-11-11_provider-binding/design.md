## 一、关系模型：三个正交的层

界面此前的所有歧义，都来自把这三层压成一层。

| 层 | 语义 | 物理位置 | 基数 | 谁改它 |
|---|---|---|---|---|
| **Provider（来源实体）** | 一个模型来源（自定义端点 / 订阅） | 每个 profile 的 `config.yaml` providers 段 + 同目录 `.env`（密钥） | 逻辑上一个，物理上 N 份副本 | 保存 / 删除 |
| **Binding（配置关系）** | 某 Agent 的配置里有这个 provider | 同上，按 profile 各存一份 | **多对多**：一个 Agent 可配多个 provider，一个 provider 可配多个 Agent | Agent 勾选区 |
| **ActiveModel（当前主模型）** | 某 Agent 此刻用它 + 用哪个模型 | 网关 `model/set` 的 `main` 槽 | **每个 Agent 恰好一个** `(provider, model)` | 模型列表点选 |

三条推论，后续所有按钮都由此推导：

1. **"配了"不等于"在用"。** 勾选 = Binding 存在；「当前模型」标记 = ActiveModel 指向它。
2. **一个 Agent 可以配很多 provider，但同一时刻只有一个当前模型。** 所以"一个 profile 只能用一个 provider"是错的，错的根源是把 ActiveModel 的单值槽当成了 Binding。
3. **provider 没有全局实体。** 所以「删除提供商」= 从所有配置了它的 Agent 上移除。这句话不是妥协，是物理事实。

## 二、数据来源的修正（删除按钮死锁的根因）

`providerCatalog.ts:47-51` 已经为每条端点算出 `profiles: string[]`——**配置集合**，注释写着"删除要按这个范围收敛"。

但 `index.ts` 把它拍平成 `result.endpoints.map(entry => entry.row)`，`profiles` 被丢弃。于是删除只能退回 `profilesWithProvider(view)`（`providerViews.ts:416`），那是 `model.options` 的 **active/ready 集合**，即"在用集合"。

两个集合不相等。端点存在于某 profile 的配置里、却没进 `model.options`（例如未生效、未带模型）时，"在用集合"为空，删除被拒绝，提示"这个提供商当前没有任何 Agent 在用"——一个能看见却删不掉的行。

**修正**：`ProviderCatalogEndpoint.profiles` 必须一路上行到视图与控制器，作为唯一的"配置集合"。

| 动作 | 作用集合 | 来源 |
|---|---|---|
| 删除 | 配置集合 | `ProviderCatalogEndpoint.profiles` |
| B 策略判定（是否在用） | 在用集合 | `ProviderView.agents` 中 `state === 'active'` |
| 勾选 / 取消勾选 | 单个 profile | 用户点击的那一格 |

## 三、Agent 勾选区（每行一块）

### 3.1 形态

每行右侧（窄屏时换到行下方）一块区域，按 `snapshot.bots` 顺序铺 N 个格子，每格 = **头像 + 名称 + checkbox**。

- 头像取 `SettingsBotRow.avatar`；缺头像走确定性图腾，**不得退回首字母**（上一版坑：`providerViews.ts:11-14`）。
- 名称保留原始拼写，超出宽度按 `truncateProfileLabel` 截断。默认预算按成员格 64px 轨道、11px 字阶标定为 10 单位（完整 5 汉字 / 10 半角，截断态 9 单位 + `…`）；宽字母与 12px 大字号档由 CSS `truncate` 兜底。
- N 就是 Agent 总数，不做"N/M 生效"这种带分母的表述。

### 3.2 状态机（四种状态，无第五种）

| 状态 | 判定 | 格子视觉 | checkbox | 点击结果 |
|---|---|---|---|---|
| **当前模型** | `agent.state === 'active'` | 高亮描边 + 「当前模型」标 | 已勾选，**禁用** | 不可取消。悬停说明：该 Agent 正在用这个模型，请先在模型列表里换掉 |
| **已配置** | `agent.state === 'ready'` | 常规 | 已勾选，可操作 | 取消勾选 = 从该 Agent 删除该 provider |
| **未配置** | `agent.state === 'absent'` | 弱化 | 未勾选，可操作 | 勾选 = 把 provider 配置到该 Agent（见 3.3） |
| **读取失败** | `agent.state === 'error'` | 弱化 + 原因 | 未勾选，禁用 | 不可操作。悬停显示原始原因 |

读取失败绝不能被渲染成"未配置"（Failure Is Not Empty）。

### 3.3 勾选"未配置"的 Agent：必须补密钥

硬约束：`GET /api/providers/custom-endpoints` 只回 `has_api_key` 与 `${ENV_VAR}` 预览，**不回明文密钥**。所以把一条自定义端点复制到新 Agent 时，定义（`base_url` / `model` / `models`）可以复制，密钥不能直接读。

> **2026-11-11 修正**：密钥仍然不能直接从 GET 拿到明文，但网关的自定义端点把密钥存在 `key_env` 指向的环境变量里，GET 会给出 `${HERMES_CUSTOM_<ID>_API_KEY}` 预览。只要另一个成员还持有这条端点，客户端就可以按这个变量名调用 `POST /api/env/reveal` 读出明文，再随保存写进目标成员。因此交互不再无条件要求重输：先复制，复制不到才补密钥。
>
> **网关取证（0.22.5 源码）**：
> - `hermes_cli/web_routers/config_env.py` 的 `_api_key_display`：`key_env` 存在时返回 `api_key_preview = f"${{{key_env}}}"`；明文 `api_key` 走脱敏预览。
> - 同文件 `POST /api/env/reveal`：请求体 `EnvVarReveal { key, profile? }`，按 `body.profile or profile` 读取该 profile 的 `.env`，返回 `{ key, value }`；限流 5 次 / 30 秒，受 `_require_token` 保护，Desktop 的原生 HTTP principal 可通过。
> - 同文件 `_write_custom_endpoint` 明确拒绝把 `${VAR}` 形态当 `api_key` 写回（会 400），所以复制路径必须是"reveal 明文 → 再保存"，不能直接透传预览串。
> - 本仓库不 vendored 网关源码；以上取证来自 `NousResearch/hermes-agent` tag `v0.22.5` 的 `config_env.py`。若目标网关没有该路由，调用会返回 404/405，客户端降级为 `transport` 错误并允许手填，不会静默假装复制成功。

交互因此分两步，不做静默成功：

```
勾选未配置的 Agent
  ├─ 自定义端点：该格子进入「待补密钥」态，展开一行
  │     「为 {Agent} 配置 {provider} 需要 API Key」
  │     [输入框] [确认] [取消]
  │     ├─ 确认 → 写入 → 成功后回填为「已配置」
  │     └─ 取消 → 回滚勾选，不留半成品
  └─ 订阅：客户端没有任何接口能复制登录态（share_auth 下新 profile 只读回落 default 的 auth.json，
        不可写入）。该格子勾选框禁用，提示「订阅需要在该 Agent 上单独登录」，
        并给「去登录」入口（打开添加弹窗，预选该订阅与该 Agent）。
```

不允许"只写不带密钥的条目"：那会产生一个看起来存在、实际发不出请求的 provider，比不写更糟。
也不允许伪造订阅绑定：登录态只能由目标 profile 自己走一次 OAuth 得到。

### 3.4 首次跨 profile 写入的全局副作用（必须提示）

网关在请求的 profile 不是当前 profile 时，会调用 `activate_multi_profile_hosting()`，把网关进程一次性切成多 profile 托管并冻结 launch env；此后未带 scope 的凭据读取 fail closed。

因此勾选区第一次发生跨 profile 写入时，界面必须给一次明确提示，写入后回归主流程验证（会话列表、发消息、模型切换）。这不是可选项，属于状态机的一部分。

## 四、删除：B 策略

用户选择：**先把这些 Agent 改到别的模型，否则禁止删除。**

| 条件 | 行为 |
|---|---|
| 配置集合为空 | 不出现该行（数据不一致，记 warn，不弹"没有 Agent 在用"） |
| 存在 `active` 的 Agent | **禁止删除**。确认框改为不可删除说明，列出 Agent 名单，每项给「去切换模型」入口 |
| 无 `active`，配置集合非空 | 逐个 profile 执行 `DELETE /api/providers/custom-endpoints/{id}?profile=<name>`，逐项回报成败 |

- 删除**不依赖**"在用集合"，只依赖"配置集合"。
- 部分失败：已删的保持已删，未删的保留勾选，行内红字列出失败 profile 与原因，**不得** toast「已删除」。
- 全部成功：行消失。
- 删除与"取消全部勾选"是同一个结果。删除按钮是它的快捷方式，可点条件相同。

### 5.1 主面板

| 编号 | 按钮 | 作用对象 | 点击后 | 禁用条件 | 失败表现 | 可撤销 |

## 六、测试连接的三态

`normalizeProbe`（`providerAdmin.ts:273-286`）目前把 `ok !== true` 与 `message` 非空一律归为 `warning`，于是"可达 + 密钥被拒"输出成"端点可达，但未通过校验 · The endpoint rejected the API key."——前半句说没事，后半句说密钥错了，还混着英文原文。

| 实际结果 | 语义 | 颜色 | 主文案 | 次要行 |
|---|---|---|---|---|
| 可达 + 校验通过 | 可用 | 成功 | 连接正常 · 发现 N 个模型 | — |
| 可达 + 认证失败 | 需用户处理 | 错误 | 密钥被拒绝，请更新 API Key | 网关原文，可复制 |
| 不可达 | 需用户处理 | 错误 | 连不上（DNS / 超时 / 连接被拒） | 原始原因 |

**待确认**：网关 `validate` 是否返回可区分"认证失败"的字段。若无，只能按 message 归类，属脆弱实现，须在文档标注并在网关升级后替换。

## 八、验收标准（EARS）

```
WHEN 用户勾选一个未配置的 Agent（自定义端点）
THEN 该格进入待补密钥态并给出密钥输入，不得直接写入无密钥条目。

IF 用户在待补密钥态取消
THEN 勾选回滚，且不产生任何 profile 上的残留配置。

WHEN 某 Agent 的当前模型正指向该 provider
THEN 该 Agent 的勾选框禁用，且删除按钮禁用并列出受影响的 Agent 名单。

WHEN 用户取消勾选一个已配置且非当前模型的 Agent
THEN 只从该 Agent 删除该 provider，其余 Agent 的配置与勾选不变。

WHEN 用户删除一个没有任何 Agent 在用的 provider
THEN 从所有配置了它的 Agent 上移除，全部成功后该行消失。

IF 删除过程中某个 Agent 失败
THEN 已删除的保持已删除，未删除的保留勾选，行内列出失败 Agent 与原因，且不出现"已删除"提示。

WHEN 用户点击「测试连接」且结果通过
THEN 显示「连接正常 · 发现 N 个模型」，且草稿中的地址与模型字段不发生任何变化。

IF 测试结果中密钥被拒绝
THEN 主文案为「密钥被拒绝，请更新 API Key」，网关原文只作为次要行出现。

WHEN 保存成功
THEN 弹窗关闭，列表页给出成功提示，且该 provider 的勾选状态反映真实写入结果。

IF 某个 Agent 读取失败
THEN 该格显示失败原因并禁用，绝不可渲染成"未配置"。
```

## 九、明确不做

| 不做 | 理由 |
|---|---|
| 事后把已有 provider 追加到新 Agent 且**其它成员也没有可读密钥** | 没有来源可复制；客户端不能凭空恢复明文，只能让用户手填一次 |
| 把脱敏预览（`sk-…9f2c`）当密钥写回 | 掩码不是密钥，写进去只会得到一条永远 401 的端点 |
| 一次性跨 provider 批量操作 | 每个写入都可能触发多 profile 托管切换，副作用叠加不可控 |
| 为订阅勾选新 Agent 时重新走 OAuth | 登录态在 share_auth 下由新 profile 只读回落 default；失败时引导去登录，不伪造授权 |
| 在行内展示"N/M 生效"这类带分母的计数 | 用户读不懂分母；勾选区本身就是全集 |
