## 一、排版与交互铁律

1. **一行一项，垂直单列**
   - 所有表单项垂直排列，每行只承载一个字段；
   - 严禁 `grid-template-columns: 1fr 1fr` 之类的并排两项布局；
   - 能力条目（Toolsets / Skill / MCP）内部同样逐项独占一行。

2. **头像编辑贴合头像本体**
   - 鼠标悬停在中间（选中）头像上，即时显示半透明编辑遮罩 + 更换头像图标；
   - 点击直接调起系统文件选择器，选择后客户端等比裁剪并即时替换预览；
   - 工具条提供「恢复默认头像」，清除自定义图片后回退到名称派生的几何头像；
   - 不设独立「头像行」，不占额外版面。

3. **不出现装饰性辅助线**
   - 头像滑动区不绘制任何居中准星、椭圆框、虚线框等辅助标记；
   - 选中态仅由尺寸、描边、名称亮度表达。

4. **一行 5 个头像**
   - 滑动区固定在一行内展示 5 个 BOT 头像，槽位步进按视口自适应并让开左右 44px 导航按钮；
   - 中间头像最大（76px），两侧依次缩小（约 58px、40px），最外侧不裁切、不越界；
   - 透明度下限锁定 0.55，保证最外侧头像仍可辨识，不允许出现「读成 3 个」的效果；
   - 滑动时槽位连续位移，BOT 数量 ≥ 5 时环形衔接；不足 5 个时按实际数量平铺，不做无意义的重复克隆。

5. **不设搜索框**
   - 工具条只保留「恢复默认头像」，不提供名称/ID 检索入口；
   - BOT 切换一律通过滑动区完成。

6. **术语直白**
   - `MCP` 就叫 **MCP**；
   - 技能插件就叫 **Skill**；
   - 不出现「一级常驻」「防溢出」「探活绿灯」「英雄传送带」等自造词。

## 三、功能点与界面落位对照

| 需求编号 | 功能 | 界面落位 | 交互 |
|---|---|---|---|
| F-01 | BOT 切换 | 顶部头像滑动区 | 滚轮、拖拽、点击两侧头像；松手吸附居中 |
| F-02 | 快速检索 | **本期不做（搜索框已移除）** | 仅靠滑动区切换；BOT 数量较大时改由后续版本的分组或筛选承担 |

| F-05 | 克隆 BOT | 底部「新建 / 克隆」 | 选择源 BOT，继承配置 |
| F-06 | 默认 BOT 保护 | 基础信息开关 | 界面不提供删除入口 |

| F-08 | 头像上传与恢复 | 头像悬停遮罩 + 工具条 | 点击上传（≤2MB），一键恢复默认头像 |

| F-10 | 绑定模型 | 基础信息下拉 | 离线模型置顶并标注不可用 |

### 4.1 使用红线

1. **`--faint` 不得承载任何解释性正文**。它只用于非活动状态点、行号、装饰图标。正文与说明一律用 `var(--muted-foreground)`，ID 等次要标识用 `var(--secondary-foreground)`。
2. **头像首字母与按钮文字不得硬编码 `#fff`**。统一走 `var(--foreground)` / `var(--primary-foreground)`，随皮肤翻转。
3. **开关旋钮不得硬编码颜色**。关闭态 `var(--card)`，打开态 `var(--primary-foreground)`，保证旋钮与轨道对比度 ≥ 3:1。
4. **`--warning` 在浅色下对白底仅 2.15:1**，只可用于圆形标记点并加 `1.5px solid var(--card)` 描边；任何警告**文字**必须用 `var(--destructive)`。
5. `.switch`、输入框、按钮必须写 `font-family: inherit`，避免 UA 默认字体混排。

### 4.2 门禁覆盖缺口（需另行处理）

`scripts/gates/lib/changed.mjs` 对 `docs/` 前缀直接 `return false`，因此 `docs/prototypes/**/*.html` 从不被 `theme/no-inline-hex`、`typo/no-literal-font-size`、`theme/ghost-token` 扫描。**原型文件的「门禁全绿」不构成任何合规证据**，必须以本表逐项人工核对。
